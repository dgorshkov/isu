In reading order, not alphabetical. A list sorted by title is one where getting started comes fourth, and the first two pages below are the two worth reading before deciding anything.

  • Getting startedFrom an empty repository to a claimed issue, with nothing installed but isu and the git it shells out to.
  • The data modelAn issue is a folder.
  • Derived statusesStatus is never stored.
  • The check catalogueisu check runs isu's rules over the repository and over what your branch proposes.
  • isu's JSON outputEvery isu command supports --json, because half the people reading its output are agents.
  • Importing from GitHub IssuesGitHub Issues is the one importer version 1.0.0 will ship, and that is a decision rather than an omission.
  • What isu does not doA tool that lists only what it can do is a tool you find the edges of in production.
  • The design recordThis is why isu is built the way it is: the decisions that were argued about, the measurements that settled them, and the ones that were reversed after a test proved them wrong.
  • First contact with real repositoriesEverything before this ran against fixtures written by the same person who wrote the assumptions, so this is the first place the world gets a vote.

Every sample on this site was produced by running isu against a repository the site's build creates from scratch. Apache-2.0.
